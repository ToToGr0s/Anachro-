Règles de code
  1. Pas de Find / FindObjectOfType / GetComponent dans Update. Références via l'inspecteur ou cache dans Awake.
  2. Singletons : seulement MatchManager et les services de Core. Pas de nouveau sans en parler.
  3. Valeurs d'équilibrage dans des ScriptableObjects. Rien en dur dans le code.
  4. Events C# pour découpler. Monde, UI, audio écoutent MatchManager, ne le modifient jamais.
  5. L'UI ne touche jamais le réseau. UI → gameplay → RPC.
  6. Règles partagées client/serveur = fonctions pures. Ex : validité d'une pose, utilisée par l'aperçu et par le serveur.
  7. Commentaires = le pourquoi. // TODO (Prénom) : pour ce qui reste.
Règles réseau (FishNet, l'hôte = serveur)
  1. L'hôte décide de tout : phases, rôles, pose, tirs, munitions, capture, victoire. Le client envoie des intentions, jamais des résultats.
  2. Toute RPC client → serveur est hostile. Vérifier rôle, phase, cadence, distance, état.
  3. Aucun secret en SyncVar. Le rôle passe par TargetRpc, « est un anachronisme » reste sur le serveur.
  4. SyncVar = état, RPC = événement. Animations et FX calculés en local.
  5. PNJ et méchant : synchro strictement identique. Même NetworkTransform, même fréquence, Animator par la vitesse. Sinon le méchant se repère.
  6. Le temps en ticks (TimeManager), pas Time.time côté client.
  7. Code des deux côtés protégé par IsServerInitialized / IsOwner, méthodes serveur en [Server].
  8. Tester avec hôte + 2 clients, et chaque semaine à 120 ms / 2 % de perte.
  9. Seul point client-autoritaire : le mouvement. Pas de prédiction / réconciliation.
  10. Vocal de proximité pour tous, sans indicateur au-dessus des têtes. Sinon le méchant qui parle est repéré.
